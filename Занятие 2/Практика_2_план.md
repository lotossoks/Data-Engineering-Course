# Практика 2. Проверка оплат и первая покупка клиента

Работайте по [стартовому ноутбуку](Практика_2_старт.ipynb) сверху вниз. Запросы можно выполнять в ноутбуке или DBeaver. Поля с пометкой `todo` допишите самостоятельно; таблица SQL-приёмов ниже служит шпаргалкой.

## Бизнесовая задача

CRM-команде интернет-магазина нужен список клиентов с датой первой подтверждённой покупки. Перед этим нужно проверить качество связи заказов и платежей: у одного заказа бывает несколько платежных операций, а статус `paid` не всегда подкреплён успешным платежом.

Постройте две связанные витрины в PostgreSQL:

1. `practice_paid_order_checks` — **одна строка на заказ со статусом `paid`**. В ней видно, сколько успешных операций есть у заказа и когда прошла первая из них. Заказ без успешной операции остаётся в таблице.
2. `practice_customer_first_purchase` — **одна строка на каждого клиента**. В ней указан первый подтверждённый заказ и число часов от регистрации до его оплаты. Клиенты без покупки тоже остаются.

В этой задаче подтверждённая покупка — заказ со статусом `paid` и хотя бы одной операцией `payments.payment_status = 'success'`. Для суммы подтверждённых заказов берите `orders.total_amount` один раз на заказ. Сумму операций из `payments` используйте только для диагностики: повторный платёж и оплата частями имеют разный смысл. Это учебная метрика текущего состояния заказов, а не бухгалтерская выручка.

## Поля двух витрин

| Витрина | Поля | Смысл |
|---|---|---|
| `practice_paid_order_checks` | `order_id`, `customer_id`, `total_amount` | Идентификаторы и сумма заказа из `orders` |
| `practice_paid_order_checks` | `first_paid_at` | Время первой успешной операции; `null`, если такой операции нет |
| `practice_paid_order_checks` | `successful_operations_count` | Число успешных операций; `0`, если их нет |
| `practice_paid_order_checks` | `successful_amount` | Сумма успешных операций; `0`, если их нет. Это диагностическое поле, не сумма заказов |
| `practice_customer_first_purchase` | `customer_id`, `city` | Клиент из `customers`; по одной строке даже без покупки |
| `practice_customer_first_purchase` | `first_paid_order_id`, `first_paid_at` | Первый подтверждённый заказ и время его первой успешной операции; для клиента без покупки `null` |
| `practice_customer_first_purchase` | `hours_to_first_paid` | Часы от регистрации до первой оплаты, округлённые до двух знаков; без покупки `null` |

## Этапы работы

| Этап | Что сделать | Способ и его смысл |
|---|---|---|
| Проверить источники | Посчитать клиентов, заказы, платежи и распределение статусов | `count(*)` и `group by status` проверяют загрузку данных |
| Увидеть размножение строк | Соединить заказы `113`, `116`, `119` с платежами | Обычный `left join` показывает несколько платежей одного заказа; суммировать `orders.total_amount` после него опасно |
| Загрузить витрину заказов | Сгруппировать успешные платежи по `order_id`, затем присоединить результат к `paid`-заказам | Единственный CTE `successful_payments` возвращает одну строку на заказ; `left join` оставляет заказ без успешного платежа; `coalesce` превращает пропуски в нули |
| Изучить историю покупок | Посчитать номер и предыдущее время покупки, число и сумму заказов клиента | `row_number`, `lag`, `count/sum over` работают по подтверждённым строкам первой витрины и не схлопывают их |
| Загрузить витрину клиентов | Пронумеровать подтверждённые заказы и выбрать первый для каждого клиента | Один CTE `numbered_orders`; `left join` к `customers` сохраняет всех клиентов. Условие `purchase_number = 1` ставится в `on`, а не в итоговый `where` |
| Проверить обе витрины | Сверить числа, аномалию и отсутствие дублей; повторить загрузку | `count`, условные агрегаты, `group by ... having count(*) > 1` выявляют ошибки зернистости |

### Шпаргалка по SQL

| Приём | Пример формы | Зачем нужен |
|---|---|---|
| CTE | `with successful_payments as (select ... group by order_id)` | Вынести агрегацию платежей перед `join`; первая вставка содержит один CTE |
| Условная выборка платежей | `where p.payment_status = 'success'` | Убрать неуспешные операции до группировки |
| Агрегация до зернистости заказа | `min(paid_at)`, `count(*)`, `sum(amount)` вместе с `group by order_id` | Получить время первой оплаты и диагностические метрики без дублирования заказа |
| Сохранить заказ без оплаты | `left join successful_payments as sp on sp.order_id = o.order_id` | Не потерять `paid`-заказ, для которого не найден успешный платёж |
| Ноль вместо отсутствия операций | `coalesce(sp.successful_operations_count, 0)` | Отличить отсутствие успешного платежа от неопределённого значения |
| Номер покупки | `row_number() over (partition by customer_id order by first_paid_at, order_id)` | Найти первый подтверждённый заказ; `order_id` разрешает совпадение времени |
| Предыдущая покупка | `lag(first_paid_at) over (partition by customer_id order by first_paid_at, order_id)` | Сравнить соседние покупки клиента в отдельном диагностическом запросе |
| Итоги без схлопывания | `count(*) over (partition by customer_id)`, `sum(total_amount) over (partition by customer_id)` | Добавить итог клиента к каждой строке заказа |
| Сохранить клиентов без покупки | `left join numbered_orders as no on no.customer_id = c.customer_id and no.purchase_number = 1` | Условие в `on` ограничивает совпадение, но не удаляет клиента без совпадения |
| Часы между датами | `round((extract(epoch from (конец - начало)) / 3600)::numeric, 2)` | Получить число часов с двумя знаками; при отсутствующей дате вернётся `null` |
| Повторная загрузка | `truncate table имя_витрины;` затем `insert into ... select ...` | Не накапливать дубли. Это две отдельные операции: между ними таблица временно пуста |
